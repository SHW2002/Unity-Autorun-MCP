# Existing Business Script Editing Contract

This reference is self-contained within the installed Skill. The connected MCP's `get_script_guidance` and tool schemas remain authoritative for the current version.

## Source and callers

`list_scripts` accepts `kind` (`business`, `basic` or `all`) and `query`; query matches IDs, names and descriptions, not dependency edges. `get_script` accepts `scriptId` and `includeSource`; returned metadata includes `id`, `kind`, `preconditions`, `preparePlayMode`, `dependencies`, `sourcePath` and `validationError`. Inspect all relevant business metadata to find direct callers, then follow those dependency edges to identify affected transitive callers. Inspect their actual source for parameter use, assumptions and assertions; metadata alone does not establish the full business contract.

Use the registered `sourcePath` and verify that its C# attribute/class uniquely defines the requested business script. If the script does not compile or register, search the host's business source directories and match its actual ID/class before editing; stale compiled metadata is insufficient. `create_script` creates new files and refuses replacement: edit the authorized existing source with the normal file editor. Do not migrate old `Assets/AutorunScripts/Editor/` files to `Assets/Editor/AutorunScripts/` as part of a repair. Do not add or change unrelated `.asmdef` files to force compilation.

Business scripts use `UnityAutorun.Scripting`, derive from `AutoRunScript`, and declare `[AutoRunScript(id, name, AutoRunScriptKind.Business, ...)]`. Required `Preconditions` metadata and an overridden `CheckPreconditions(AutoRunScriptContext)` express their exact post-preparation start. Return null for a valid start or a concrete failure explanation. `Execute` returns `IEnumerator`; supported yields are null, nested `IEnumerator`, `context.Wait`, `context.WaitUntil` and `context.Call`. Unity coroutine handles, `WaitForSeconds`, `Task` and `WaitForEndOfFrame` are unsupported.

Every called script must be declared in `Dependencies`, including conditional calls. Child parameters are supplied explicitly and are not inherited. Missing dependencies, duplicate IDs, cycles and undeclared calls fail validation or execution. Internal refactoring may change dependency composition only when it preserves the target's starting-state, action, parameter and result contracts; the referenced source files remain protected. `OnExit(context, result)` can run after a precondition failure and must tolerate partial initialization.

## Compilation and active runs

`refresh_scripts` requests Unity asset refresh. Wait for `unity_status` compilation/update completion and inspect `compilerMessages`, then use `list_scripts`/`get_script` to check the new assembly's registration and dependency validation. Do not accept the previously loaded assembly as evidence after compilation fails.

No run may be active when source changes or refresh begins. First require `unity_status.data.scriptRunStateAvailable=true`: execution state is trustworthy only after saved run requests have been restored. When it is false, wait for the next status; persistent unavailability or missing state fields on an older connection blocks source changes and must be reported. Once available, `data.hasActiveScriptRun` is true for a pending/running script and false when no script is active; wait for false together with `data.isCompiling=false`. Poll a known current `runId` with `get_script_status` until terminal when available. Never infer runner idleness from a false active-run value when availability is false, a prior run, or from Play Mode/compilation status alone. A running C# iterator cannot survive Domain Reload; a reload failure is retained and completed actions are not automatically replayed.

## Test and regression execution

`start_script` accepts `scriptId`, string-valued `parameters` or `parametersJson` (choose one), optional `runId`, `ensurePlayMode` (default false), and `timeoutSeconds`. Numbers and booleans are strings in the parameter dictionary. Each intentional self-test/regression uses a new ID; an old ID returns its retained result instead of executing the recompiled code. Keep the same ID only for identical transport retries.

`preparePlayMode` is compiled root metadata, not a start argument. Runner preparation occurs before business preconditions/actions when caller `ensurePlayMode=true` OR root `preparePlayMode=true`; false caller input cannot disable true root metadata. Dependencies never implicitly enable preparation. Preserve the existing root declaration when editing. `start-play-mode` prepares as a root and only verifies prepared Play Mode as a child; do not toggle Play Mode from an active iterator. An absent post-start UI while stopped does not alone disprove a startup flow's post-preparation start. A known wrong starting scene/state must be reported without resetting it or inventing a run result.

`get_script_status` takes `runId` and optional bounded `waitMs`/`pollMs`; inspect `data.scriptRun` including `state`, `terminal`, `code`, `message`, `callStack`, `calls`, `logs` and `artifacts`. States are pending, running, succeeded, failed, canceled and timedout. A terminal failure has `ok=false` and retains the full run evidence. Poll only while nonterminal. `cancel_script` takes `runId` when the user requests cancellation; never cancel another run solely to edit its source.

Check actual declared final assertions and, when needed, narrow `get_ui_state`/`wait_for_ui_state` evidence. UIState proves observed structured UI values, not pixel appearance or arbitrary host business state; use host assertions or actual screenshots when the requested result requires them. Sensitive UI values remain masked unless their reading is authorized. Regress affected callers one at a time using their own declared starts and parameters, preserving the current game state at every exit. If their starts cannot be met, report unverified callers rather than resetting or claiming coverage.
